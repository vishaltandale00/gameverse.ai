# Cartridge reconstruction

`tools.roundtrip` extracts a complete addressed partition and reconstructs a
cartridge from the extracted component artifacts. The reassembler never opens
the manifest's original cartridge path. That path is provenance only. It checks
full coverage, bounds, overlaps, hashes, component identity, pinned dependencies
and local artifact paths before creating new output files. Originals and prior
outputs are immutable. Relocation is unsupported by this exact backend.

Run an exact preservation baseline with a new output directory:

```sh
python3 -m tools.roundtrip roundtrip \
  --source 'local/roms/Metroid - Zero Mission (USA).gba' \
  --output local/roundtrip/mzm-preservation-new \
  --game-id metroid-zero-mission
```

Run the demonstrated known-source component and complete object partition:

```sh
python3 -m tools.roundtrip mzm-source-roundtrip \
  --source 'local/roms/Metroid - Zero Mission (USA).gba' \
  --source-tree local/game-builds/mzm-us-baseline \
  --output local/roundtrip/mzm-object-source-new \
  --game-id metroid-zero-mission
```

This bounded source provider reuses the existing MZM make/compiler setup and
forces `src/samus.c` compilation plus linking, with a 60-second timeout. It reads
the resulting ARM ELF load segment to reproduce the actual 104-byte
`SamusUpdateDrawDistanceAndStandingStatus` function at its original address.
It does not obtain those regenerated bytes from the original cartridge.

The linked map identifies the other object sections. Each captured section is
checked against the ELF and original cartridge; header bytes changed by the
existing `gbafix` step remain opaque. File-backed ROM sections are captured;
RAM/BSS are not incorrectly treated as ROM storage. The manifest records two
pinned table dependencies of the regenerated function. Remaining semantic
dependencies and logical component boundaries remain unknown.

The demonstrated `local/roundtrip/mzm-object-source-v3-20261016` run has:

| Stratum | Components | Bytes | Meaning |
| --- | ---: | ---: | --- |
| object-captured | 728 | 7,900,171 | Linked object section ownership and bytes; no fresh IR regeneration claim |
| source-regenerated | 1 | 104 | Fresh source compile/link, exact function bytes |
| opaque-preserved | 5 | 488,333 | Header postprocessing, linker gaps/padding and unassigned spans |

The 672 source-object ownership groups are component scaffolding, **not closed
gameplay prefabs**. Object ownership alone proves neither dependency closure nor
interchangeability. Source regeneration is distinct from recovered IR lowering.
The unlockable NES payload remains preserved data even where its containing
object is identified. There is no whole-game semantic reconstruction claim.

Each successful combined run emits `manifest.json`, `components/`, retained
evidence, `rebuilt.gba`, `layout.json`, `comparison.json` and `timing.json`.
The source provider also retains its build receipt, log, linked map, object
inventory and extraction profile in the sibling `-source-provider` directory.
The comparator keeps raw byte equality distinct from semantic proof.

Other known-source games use the reusable pinned ELF/map provider:

```sh
python3 -m tools.roundtrip elf-roundtrip \
  --provider-profile research/ir-workshop/roundtrip-20261016/emerald/elf-capture-profile.json \
  --output local/roundtrip/emerald-elf-new
```

The `gameverse.elf-capture-profile/1` input pins the original, ELF, linker map and
optional upstream evidence by SHA-256, with an explicit game ID and ROM base.
Optional source-root metadata is hashed as provenance. It does not establish
that a captured object was freshly compiled. The provider accepts wrapped GNU
map input sections and archive members, maps file-backed virtual addresses to
physical ROM load addresses, and excludes BSS and non-ROM sections. Any explicit
postprocessing exception is limited to its declared byte range: affected bytes
remain opaque and a mismatch outside that range fails. No header exceptions
were needed for the demonstrated Emerald run.

`local/roundtrip/emerald-elf-20261016` reconstructs all 16,777,216 bytes with zero
differences (SHA-256 `a9dec84dfe7f62ab2220bafaef7479da0929d066ece16a6885f6226db19085af`).
Its 1,174 components contain 1,122 object-captured sections (12,207,236 bytes)
and 52 opaque spans (4,569,980 bytes). Its 883 ownership groups remain
scaffolding, with zero regenerated IR bytes and unknown semantic closure.
The existing exact source-build receipt is retained as pinned upstream evidence;
this extraction did not compile the game. Total elapsed time was 1.041933833
seconds, including 0.583092458 seconds of provider work. Independent artifact
and layout QC passed in 0.127126 seconds; its receipt is
`local/roundtrip/qc-review-20261016/emerald-qc.json`. No comparable prior generic
Emerald extraction measurement exists yet.

Observed equivalent warm runs on the same machine: v2 took 2.654234375 seconds;
v3 took 0.72970275 seconds after reusing the original SHA-256 once instead of
rehashing the 8 MiB input for every component. Those are complete CLI durations,
not clean build times. Per-stage build duration is separately recorded; queue
and simulation measurements are unavailable. The earlier failed map extraction
is retained in `mzm-object-source-20261016-source-provider` with its failure
receipt; the pre-`gbafix` ELF header mismatch was made explicit instead of
claiming it matched.

Standalone artifact-only reassembly can run after removing access to the
original cartridge:

```sh
python3 -m tools.roundtrip reassemble \
  --manifest local/roundtrip/mzm-object-source-v3-20261016/manifest.json \
  --output /tmp/mzm-reassembled-new.gba
```

`native_provider.py` implements the separate relocated Aria parity demonstration.
Its explicit generated hook/payload/output partition has its own assembler and
retains a raw byte mismatch against the original; see that provider's receipt.
