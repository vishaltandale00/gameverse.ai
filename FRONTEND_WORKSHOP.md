## Mechanic graph assembly

Mashup includes an editable mechanic graph over the published finite component contracts. Add component instances, bind fields to explicitly owned/shared state, set semantic units and frames, configure arguments, and order invocations. Advanced technical wiring examples retain their source scope internally; primary choices describe player-facing systems and responsibilities. Source data keeps partial source systems, prior static analyses and executable finite subsets distinct.

The primary flow starts with a player experience and its required or optional responsibilities. Candidate source bundles show what is implemented and what is still missing. **Add ready prefab** imports a recorded assembly with its actual package pins, state ownership and invocation order; reusing a bundle for another responsibility references that same module rather than duplicating it. Source-only facets remain explicit gaps. Minish learning controls update the prefab’s actual learned-state calls before capability refresh. The MZM post-contact inspector accepts damage, HP and bounded eligible updates, then executes the emitted recovered C core on the host; it does not run an original-ROM combat encounter or create a game.

**Validate bindings** posts the graph to `/api/ir/assembly/validate`, which invokes the real Composer through `tools/behavior_ir/assembly.py`. Validation checks published package identities and actual behavior/receipt hashes, ownership, storage widths, domains, units, frames and invocation bindings. Its result is `binding_valid_obligations_unproven`: accepted wiring does not prove gameplay, whole-system recovery or a complete executable L2. Unsupported services and conversions fail closed. Validation creates no ROM, registration or native run; graphs can be exported separately. Original role presets and their build/Add to Play workflow remain available below this graph.

Prefab imports use fixed allowlisted `/api/ir/system-prefabs/:id` routes and require fresh Composer admission before returning the normalized graph and source hash. The nine entries are MZM post-contact damage/reaction, Minish learned-state refresh, Sonic air advance, four Aria category acquisition specializations, the Wario protection query subset, and Tekken geometry initialization/publication. Their boundaries remain visible; none is a complete source game system. Aria selects one specialization before import and replaces that module’s prior specialization rather than cloning all four categories.

Use **Experience blueprint** to choose among the varied player-facing plans, or **Reconstruct a game** to inspect a published source-game core-loop map. All 33 original source games have inspectable partial reconstruction maps. Ready coverage counts only phases with a usable registered prefab. Source-only and internally consumed phases retain their missing prerequisites and receive no ready credit. New registered maps and modules load from the catalog without copying actor or world state across role facets.

Additional source-game prefabs arrive through the fixed, server-owned `ontology/game-system-prefabs/manifest.json` and explicit `deliveries.json` registry. The endpoint verifies each registered graph and retained receipt hash, confines both to that delivery’s research directory, rejects symlinks/path traversal, and runs current Composer admission before import. The nine established entries remain available. Registered descriptors use immutable central snapshots named by their exact SHA256; the endpoint checks that the selected prefab belongs to that snapshot. Raw worker paths remain provenance references and cannot silently change an accepted version. The catalog exposes full registered delivery maps and bundles, preserving missing phases and source scope; registration does not qualify a whole reconstructed game. The existing cache watches both registries and their explicitly registered delivery files, so later additions can appear without another shell build.

The MZM inspector uses GET `/api/ir/systems/mzm-damage-reaction` for current package/binding readiness and POST for bounded host execution. Only integer damage/HP 0–65535 and eligible updates 0–64 are accepted; requests are capped at 8 KiB, one in flight, 15 seconds and 256 KiB output. Compile/run happens in temporary files with fixed arguments. Measured host compilation was about 43 ms in the retained HTTP check, so no compile cache was added.

The local endpoint accepts same-origin JSON up to 256 KiB, one validation at a time, with a ten-second subprocess limit. The static shell retains the catalog, graph editor and source evidence; server validation requires the local development server. Published component/source/example changes refresh the existing source-only data cache without watching its own output.

## Executable selection and generation

The Workshop reads the compiler's actual `generate.py --options` and executable ontology catalog. Movement, combat and progression selectors identify concrete packages and show their qualification, typed ports, units, dependency services, limitations and local availability. Changing a selector changes the submitted compiler request. Source-world chips follow the packages actually used; choosing an unsupported source world blocks generation with a reason.

The current qualified combinations include Sonic/Zero Mission, Aria/Zero Mission and Mario World/Sonic/Zero Mission movement; Zero Mission impact; and either Zero Mission equipment acquisition or Minish persistent inventory/skill derivation. This list evolves through compiler options, without frontend hardcoded presets. Storage-qualified records whose semantic adapters remain pending are not selectable merely because they appear in the catalog.

**Build & qualify GBA** persists a versioned request, context and server-resolved package hashes, then invokes the actual IR compiler and bounded native qualifier. The UI displays receipt phases, diagnostics, typed conversions, ROM identity, native final facts and actual PNG/MP4 artifacts. There is no simulated job status. **Add to Play** becomes available only after build and native qualification pass, verifies the ROM hash and explicitly registers the cartridge in normal collection Play. Existing cartridge/core/profile progress identity is retained. The v1 arcade remains FireRed-bound.

The clean-ROM world, input/jump policy, projectile/gate orchestration and graphics are explicitly authored IR around recovered executable mechanics. The current output is a bounded connected game slice, not an automatically reconstructed full campaign. Optional story/style choices remain collapsed creative notes; they are not executable packages or a natural-language planner. Similarity on the embedding map does not prove typed compatibility.

See [the operator runbook](OPERATIONS.md) for exact requests, CLI and HTTP interfaces, private package setup, time limits, native QA, bot/provider selection and model credentials. Deterministic IR generation and qualification need no model key. Static shell builds have no generation API or private cartridges.

## Explore and incremental research

Explore retains the library, graded component/portrait summaries and cached embedding views. Neighbor rankings use original per-view distances rather than positions on the 2D projection. Text axes may be unverified model recall; capture axes cover limited observations. Source-supported partial, observed and model-prior claims stay distinct. Raw pseudo-C counts and decompiler leads are not promoted into executable compatibility.

The development server watches canonical `ontology/games/*.yaml` and `ontology/portraits/*.json` metadata plus the four public progress inputs (automatic-IR status, Mario coverage/targets and the resumed fleet dispatch summary) through the existing on-demand cache. The Research progress panel distinguishes retained native/typed subsets from discovery targets and static packets, with source hashes and snapshot dates. Per-game inspection includes the fleet next action without promoting packet readiness to executable compatibility. `/research/status.json` reports freshness, counts and errors. The interface checks on focus/visibility and every 20 seconds while idle, preserving selections and notes, deferring while editing and skipping refresh during active GBA sessions. Failures retain the last successful snapshot. Embedding-map date is separate from source research date.

Source-only export uses existing PyYAML, retains embedding coordinates/rankings and makes no model call:

```sh
python3 scripts/export-research.py . --source-only
```

Set `RESEARCH_PYTHON` if the server's default Python lacks PyYAML. Static builds keep their last snapshot. Private ROMs, raw vectors, credentials, source checkouts, generated packages and recordings remain ignored local artifacts.
