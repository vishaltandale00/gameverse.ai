# Native FireRed region-map source provider

`tools/whole_game/single_rom/region_map.py::stage_region_map(base, donor, out, report_dir=None)` imports the complete donor `region_map.c` and `map_preview_screen.c` into an isolated staged Emerald tree. It retains all 140 map-screen functions and 14 map-preview functions, including allocation, opening/closing animation, tasks, window buffers, cursor input, Sevii selection, Fly destination validation, cancellation and resource release. It does not replace an unavailable screen or callback with success.

The provider includes all 75 original files under donor `graphics/region_map` and `graphics/map_preview`, all four map-layer headers, all 28 UI text constants, donor map-section names and geometry tables. The generated C tables follow the donor JSON templates and exact `cleanString` rule; raw donor map-section numbers stay intact. Function/static data names and donor flag/map/heal/audio constants use their imported namespaces.

Native `CB2_OpenFlyMap` and `FieldInitRegionMap` dispatch to this provider in Kanto; the existing Emerald bodies remain available for Hoenn. The original `ShowTownMap` special calls the imported screen and retains its actual Quest Log call and return-to-field callback. The source Fly destination table uses the appended real native heal IDs supplied by `travel.py`, rather than selecting points on a Hoenn picture. Source preview tasks expose `FR_ForestMapPreviewScreenIsRunning` for the campaign whiteout gate.

`firered_region_map.h` exposes `FR_GetMapName`, `FR_GetMapNameGeneric`, `FR_InitRegionMapWithExitCB`, `FR_CB2_OpenFlyMap`, `FR_ShowTownMap` and the stairs-policy backing variable. `firered_map_preview_screen.h` exposes the complete namespaced donor preview API. Shared global `GetMapName` remains unchanged: caught-location callers must choose the donor lookup from the Pokémon's origin-game plus raw eight-bit met-location pair, rather than the player's current region. The encounter owner implements origin-game selection; summary UI qualification is separate.

The real Quest Log state and services are required externally: `FR_gQuestLogState`, `FR_QuestLog_CutRecording`, and `FR_SetUsedFlyQuestLogEvent`. Preview source retains its playback gate. No fake idle state or no-op event function is emitted. The movement owner consumes `FR_gExitStairsMovementDisabled` according to the donor stairs policy.

Three focused checks pass in 0.166 seconds. A compiled C data probe compares all 2,640 cells of the original and staged Kanto/Sevii layer arrays. Additional checks cover original Fly/preview callbacks, source text and full asset hashes. This is source/data validation, not native UI execution. No ROM build, browser, model call, or gameplay run was performed. Native GPU/text/window ABI, font appearance, converted graphics, party-menu return and complete UI lifecycle remain gated pending the diagnostic compile and native qualification. The first failed arbitrary asset-count fixture is retained in `verification.json`; the corrected test compares the complete source inventory.

`region-map.json` pins source inputs and staged outputs. Its measured stage time is separate from the test-suite duration. There is no comparable pre-implementation baseline for this new stage, and compiler subprocess timing is not separately available.

## Actual compiler repair evidence

`targeted-agbcc.json` records successful compilation of `event_object_movement.c`, `firered_region_map.c` and `firered_map_preview_screen.c` with the existing agbcc flags. Work used a private copy-on-write clone of failed build `20261016T171250Z-eb5bd6a023b8`; neither its frozen source nor canonical decompositions were edited. The first targeted attempt took 1.8133 seconds and retained its errors; the remaining two affected units passed in 1.0506 seconds after generator fixes. Preview compilation had already passed and was not repeated. Asset cache state and scope differ between attempts, so these are repair timings, not a speedup comparison. Seven combined focused checks pass in 0.380 seconds.

The fixes preserve actual source bytes and indices: nested graphics includes use sibling paths, donor animation constants are imported, the preview uses the native `field_screen_effect.h` declaration, `DPAD_ANY` keeps donor bytes `F8 0C`, JSON labels follow UTF-8 byte iteration, map pairs expand to the shared group/number macros, and the repeated-key macro reads the same source field. Linking and native UI/gameplay execution remain unverified.
