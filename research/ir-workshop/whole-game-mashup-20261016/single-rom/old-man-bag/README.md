# Original Old Man bag events on the shared native bag

`stage_old_man_bag(emerald_source, firered_source, output_tree, report_dir=None)` stages an independent Old Man tutorial entry point, `FR_InitOldManBag`, declared in `include/whole_game_old_man_bag.h`. It runs after the native UI/tutorial stages and uses the imported donor audio IDs. Canonical source trees remain unchanged.

The donor task is the timing oracle: tutorial-active ticks 102 and 204 switch from Items to Key Items and then Poké Balls; tick 306 selects Poké Ball and draws Use/Cancel; tick 408 removes the context window, destroys the list once, restores the player's bag and begins the exit fade. Palette fade and delegated pocket-transition tasks pause tutorial ticking. Input remains suppressed during both the tutorial task and pocket animation. The selected Poké Ball survives restoration so the original battle controller can continue its catch demonstration.

Native pocket IDs are mapped by semantic names. Emerald's order is Items, Balls, TM/HM, Berries, Key Items; blindly advancing twice would show TM/HM. The tutorial has a private Items → Key Items → Balls ring, used by the native transition preview and commit. Other menus retain their normal pocket order.

The composed game deliberately uses its shared native bag renderer, artwork, text/item/icon rendering, window layout and transition-animation ownership. The original FireRed event semantics, demo inventory, context selection and restore-before-exit order remain authoritative. Native transition animations complete before the tutorial task resumes; the active-tick events remain the original source values. This presentation policy was explicitly approved for the composition and is not classified as a missing feature.

The tutorial backs up and restores Items, Key Items, Balls, the registered item and all native pocket cursor/scroll state. TM/HM and Berry pockets remain untouched and are inaccessible to the scripted tutorial. The 408 transition owns list destruction; its private fade callback performs native sprite, palette, window and list-buffer cleanup, then returns through the native battle reshow callback. It avoids the ordinary native bag close callback's second list destruction.

Validation compiles the generated task and snapshot lifecycle against small native stubs, checks the original source event oracle, checks animation/fade barriers and selected-item restoration, and exercises allocation failure without changing persistent bag state. The complete generated `src/item_menu.c` also passes the real agbcc toolchain with the integration build's flags and preprocessor context. See `validation.json` for timings and unavailable baseline/queue/full-ROM measurements. Cartridge presentation and end-to-end battle input are not yet qualified by these checks.
