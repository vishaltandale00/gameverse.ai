# Single Emerald engine / FireRed campaign state

`tools/whole_game/single_rom/state.py:apply(staged_base, donor)` creates deterministic source patches only; canonical source directories are refused. No original tree or shared build tree was modified. `ledger.json` pins the generated source and current scope. This is partial integration and is not eligible for a full campaign claim.

## Frozen namespace

- FireRed persistent nonzero flags `1..0x8FF` become `0x1001..0x18FF`; zero remains the object no-hide sentinel. Its entire trainer defeated bank `0x500..0x7FF` remains separate. Runtime trainer IDs are offset **4096**, with the donor dummy omitted; `FR_TRAINER_NONE` aliases native zero in the encounters module. All native special trainer IDs stay unchanged. Holes/sentinels have no defeated flag in the new helper.
- Donor persistent vars `0x4000..0x40FF` become `0x5000..0x50FF`, except the explicit shared Repel counter below.
- Scratch `0x8000..0x800F` retains common ABI. Donor box ID `0x8010` maps to Emerald `0x8012`; box position `0x8011` to `0x8013`. Donor text color `0x8012` and previous color `0x8013` map to explicit new runtime slots `0x8016`/`0x8017`, with the original FireRed global names. Donor unused `0x8014` stays unused. Special flags share the original transient bank.
- Generated `include/constants/whole_game_fr_state.h` provides all `FR_FLAG_*` and `FR_VAR_*` literals. Encounters owns trainer/class/item aliases. Callers must include this header. `include/whole_game_state.h` exposes region, trainer flag, and HM permission helpers.

## Save capacity and ownership

Emerald SaveBlock1 ends `0x3D88`, with only 120 bytes to its four-sector limit `0x3E00`. SaveBlock2 ends `0xF2C`, with only 84 bytes to its one-sector limit `0xF80`. Neither can fit donor flags and vars without removing native state.

Native PokemonStorage ends `0x83D0`; its nine existing sectors provide `0x8B80` bytes. The appended 1260 bytes contain all 288 donor flag bytes, all 256 donor u16 vars, schema, a separate first-arrival initialization marker, rivalName[8], 64 encrypted donor u32 stats, two native WarpData heal locations, a heal schema, original u16 VS Seeker counter,100-byte donor rematch array, alignment padding and64-byte Fame Checker bank. New storage size is `0x88BC`, leaving 708 bytes before later world-services additions. Those additions must retain the compile-time sizeof guard. The save-runtime provider owns any subsequent compact serializer layout; this ledger describes the original chunk fallback, not that provider’s qualification. Existing box data, names and wallpapers keep original offsets and capacity. Compile-time size/alignment assertions prevent truncation. No additional save sector, stage, dependency, or CI job is added.

`save.c` uses `sizeof(struct PokemonStorage)` in the existing nine `SAVEBLOCK_CHUNK` entries; sector checksums, rotating slots and copy/load loops therefore include the tail. `load_save.c` uses the ASLR wrapper and whole-struct backups, including the new bytes. Normal/Hall-of-Fame saves and LinkFullSave include the complete PC tail. Original SAVE_LINK/SAVE_EREADER intentionally omitted PC; this transform now adds only the final PC sector to their existing replacement and signature passes. That changes those paths from five sector writes to six, with one extra signature. A compiled source dispatcher fixture verifies ordering; actual flash duration and cartridge save/reload have not run. The new save-runtime provider must supersede this partial-save adaptation if it changes slot layout. Fresh unified saves only are supported. The changed last-sector checksum size is incompatible with legacy saves; no migration is claimed.

InitEventData explicitly zeros the extension and stamps schema `0x57470101`, including when starting another new game in the same process. `ResetPokemonStorageSystem` alone is insufficient because it clears boxes individually. Campaign worker owns running original `FR_EventScript_ResetAllMapFlags` and renewable item initialization exactly once, using `campaignInitialized`; donor new-game reset must never erase native identity/party/inventory.

One native Emerald trainer identity, party, PC, bag, Pokedex, capture and evolution engine persists through region travel. Badges/quest/trainer flags remain independent. Party-menu and automatic Surf/Dive/Waterfall permission use current region's original badge associations; Kanto has no Dive. Native map group 34 is the donor boundary. Actual source travel scene, initialization and portable-party play remain unqualified.

## Coverage and gaps

Six focused tests pass, including C compilation/execution of the exact patched pointer/get/set/new-game functions across every donor persistent flag and var, native separation, sparse trainer boundaries, box/text special vars, invalid bounds, and repeated reset. The latest six state tests and three VS tests passed together in0.414 seconds. Prior scope timings are not a comparable performance baseline; native build/save timing remains unavailable. No full build, browser, emulator or campaign was run; there is no representative earlier implementation baseline to compare.

The independent encrypted donor stat bank preserves the original source52-used/64-stored bounds and 24-bit increment saturation. Both banks are rekeyed when the native encryption key changes. Native same-named event stats dispatch by region; numeric collisions12 (fishing),32 (tower streak) and51 (Berry Crush) retain distinct semantics. Imported donor code must call FR_GetGameStat/FR_SetGameStat/FR_IncrementGameStat with donor IDs. The new reset writes encoded zero using the current key, including a reset after key rotation. Host C fixtures verify the collisions, saturation, invalid IDs and rekeying.

Explicit sharedStateAliases map FR_VAR_REPEL_STEP_COUNT4020 to native4021, FR_FLAG_SYS_WHITE_FLUTE_ACTIVE803 to nativeFLAG_SYS_ENC_UP_ITEM8AD, and black804 to nativeFLAG_SYS_ENC_DOWN_ITEM8AE. The generated namespace header and numeric helpers apply those exact exceptions; no generic story-flag passthrough exists. Both originals clear flute effects in ClearTempFieldEventData on ordinary map loads, including region travel. Repel persists its remaining-step count. Native item-use writers and donor wild consumers now share authoritative state; the compiled fixture checks native-to-donor and donor-to-native reads/writes.

Remaining responsibilities are explicit in the ledger: actual unified save/reload and checksum qualification; campaign first-arrival wiring; native regional readers such as obedience, stat badge bonuses and Fly destinations; donor non-flag state structures and active key-item service implementations. Emerald declares the FireRed key item IDs but several still use CannotUse. Retaining IDs and flags does not certify those services. Encounters owns donor trainer table import, special sentinel avoidance, and protecting 10-bit Frontier records/recorded-battle range dispatch from donor IDs. State does not default any missing source service to success.

The current VS Seeker provider is implemented and scoped-native-compiled separately. Historical generic gaps in this state ledger must be reconciled with the later subsystem ledgers; allocation alone does not certify their implementations.
