# FireRed native script opcode extension

`tools/whole_game/single_rom/opcodes.py` extracts all ten actual donor handler bodies and appends their namespaced functions to the staged Emerald script interpreter. Existing Emerald dispatch entries retain their positions; the new commands occupy `0xe3` through `0xec`. Each new table entry and emitted body has source provenance in `opcodes-ledger.json`.

The coordinator API is `stage_native_opcodes(emerald_source, firered_source, output_tree, report_dir=None, *, symbol_map=None)`. Pass the returned `handlerOpcodeMap` to `compile_macros(..., opcode_overrides=...)`. This replaces only the compiler's missing-handler guards for handlers which now have actual implementations. It does not bypass native-provider or campaign gates.

The handlers preserve donor operand widths, null-message fallback, comparison results, shared party data, dedicated text color variables and return/yield values. They call eight explicitly namespaced FireRed helpers for donor game statistics, map preview, quest log, help windows and message mode. Those helpers are **not replaced by no-ops or default-success implementations**. Missing source providers block the ledger. `FR_GetGameStat` must preserve a donor statistic bank: FireRed/ Emerald statistic slots 12, 32 and 51 differ in meaning, so the handler deliberately requires an explicit provider rather than aliasing the host getter. Provider source presence is only a necessary source-build check; its transitive ABI and gameplay qualification belongs to the native-provider ledger.

The saved isolated source-transform receipt intentionally has no state/UI/services stages applied. Its nine unresolved items are the eight helper providers and the dedicated state header. The shared coordinator must apply state first and refresh this idempotent stage after later UI/services stages if it wants current provider-presence results. The standalone generated files are under ignored `local/whole-game-mashup/emerald-firered/single-rom/opcodes-source`.

Four focused checks pass: exact extraction of all ten bodies, append-only dispatch and repeatability, canonical-input protection and overflow refusal, real helper absence gating, and successful script macro re-encoding using the returned mapping. `verification.json` records their measured duration and context. No full build, native UI execution or campaign play was run. There is no before/after turnaround baseline for this new stage; unavailable queue/build/native timings remain null.
