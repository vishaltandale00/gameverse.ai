# FireRed Pokemon Tower ghost battle source stage

`tools/whole_game/single_rom/ghost_battle.py` stages FireRed's Tower ghost rules and presentation into the isolated Emerald source tree after `battle_services`. The typed `WholeGame_IsFireRedGhost*` ABI owns the special battle state. FireRed's `BATTLE_TYPE_GHOST` bit 15 cannot be reused because Emerald uses it for `BATTLE_TYPE_TWO_OPPONENTS`.

The original FireRed Tower gate is floors 1F–7F without SILPH SCOPE. Ordinary ghosts use the original `DoGhostBattle` field/stat path, show FireRed's ghost sprite/name/intro, do not register as seen, cannot attack or be attacked, cannot be caught, take no weather damage, suppress Intimidate/Trace, and permit the player to flee. The Marowak source entry in `battle_services` selects the same ghost state or the unveiled state. The unveiled battle plays the Silph Scope animation, changes to Marowak's sprite, registers seen, permits normal combat, and still dodges balls. Ghost HUD gender/caught markers and battle-screen reshow use the typed mode.

The FireRed ghost PNG is copied byte-for-byte from the pinned donor source and compiled as native graphics. The ghost battle script and animation branches, including the Ghost Get Out task state machine and ball dodge arc, are source adaptations; the Emerald engine remains the owner of ordinary battles. The exact donor source and asset hashes are in `ghost-battle.json`. `WholeGame_FireRedGhostBattleVersion` is the global ELF witness.

Focused verification on 2026-10-16: three Python stage/source tests passed in 2.681 seconds. In an isolated copy of the retained 26-stage candidate, 13 affected C units and three battle script/animation units compiled successfully with `make -j2 -k CPP='clang -E -Wno-invalid-pp-token'` in 3.26 seconds; `arm-none-eabi-nm` found the witness in `battle_gfx_sfx_util.o`. This is a clean object-level source check, not a linked-ROM or live battle qualification. A comparable pre-change compilation duration is unavailable, so no before/after speed claim is made. The full candidate build and in-game validation remain owned by the build/qualification workstreams.
