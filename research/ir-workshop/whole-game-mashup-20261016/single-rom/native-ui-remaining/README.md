Reusable capability findings:

- Name equality is insufficient for menu substitution. The native generic party chooser's CHOOSE_AND_CLOSE path does not write the donor script result. A real selection callback must commit 8004, preserve field-return/fade/script-resume behavior, and map cancellation to donor SLOT_CANCEL=7. Relearner selection also writes relearnable-count 8005.
- Tutor IDs and eligibility tables are game-specific data contracts. The shared party engine can own learning/replacement/input lifecycle while the active donor tutor operation uses the exact donor regular/ultimate indexes and learnsets.
- Source MapHeader floor fields do not exist in Emerald. The popup extraction retains per-map source floor and raw section metadata, indexed through the source-to-merged map-group mapping; replay/map-index lifetime still requires integration qualification.
- eReader card layouts and persistent owners differ. A successful compile of a same-named Frontier field would not prove the correct source record is being rendered.
- Buffer roles are a shared ABI: nickname entry, original-name comparison and commit callbacks must use the same native gStringVar2/3 state across the whole task lifecycle.
- The original diploma's return callback body matches native fade-from-black return; this is narrow source evidence, not proof that all diploma/Pokedex engines are interchangeable.
