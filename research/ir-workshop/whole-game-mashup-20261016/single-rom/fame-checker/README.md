# Original FireRed Fame Checker in the single engine

`tools/whole_game/single_rom/fame_checker.py` stages the entire original 1,739-line Fame Checker implementation: all 64 functions, five public collector/script helpers, original selection/pick/flavor-text tasks, close/fade/return callbacks, all graphics and original text symbol references. It does not auto-unlock the collector or replace its UI with a success return.

The stage owns `src/firered_native/fame_checker.c`, `fame_checker_state.c`, `fame_checker_item.c`, public/constants headers and the original collector graphic assets. The native Fame Checker item slot is bound to its real field handler. Bag entry uses the native bag's fade and callback ownership; registered entry uses the native field fade/task/return lifecycle. Item use emits the original Quest Log item event. Collector trainer names and portraits, NPC graphics, fonts, sounds and story strings use their actual imported FireRed domains.

Persistent progress uses `gPokemonStoragePtr->wholeGameKanto.fameChecker[64]`, supplied by the state owner. A four-byte record preserves the original low two pick-state bits, twelve flavor-text bits, two unknown bits and the two padding bytes. The explicit padding representation avoids modern compiler layout differences. `donor-save-record-stride.json` records an actual pinned FireRed agbcc probe: the original donor structure occupies four bytes, hence sixteen records occupy 64 bytes.

Companion contracts are explicit: the map runtime provides actual donor-bank NPC icon creation and palette initialization; native UI provides the original dialogue frame and printer spacing; fonts provide exact `FR_FONT_NORMAL` and `FR_FONT_SMALL`; encounters provide original trainer data/portrait tables; audio provides original sound effects; scripts provide the original flavor/name/quote text labels; Quest Log records the item event. New-campaign initialization must invoke the real reset once to preserve Oak's default colored entry, and must not reset on region travel or resume.

`verify_agbcc` reuses existing pinned gbagfx, preproc and agbcc executables. It converts the real source graphic assets and compiles the three emitted units, plus native `src/item.c` when present, with warnings treated as errors. This is narrowly scoped compilation, not a full ROM build. `verify_progress_state` compiles the actual emitted collector helpers and checks 144 flavor cases, 270 pick-state cases, original reset/unlock behavior, bounds, colored-entry non-downgrade and the exact 64-byte storage layout.

Five source-only tests cover complete function closure, exact asset hashes, actual script/resource domains, real item entry paths, durable progress, deterministic regeneration and immutable-source rejection. Receipts preserve source/asset hashes and measured durations. No previous collector port existed, so a comparable before measurement is unavailable. ROM linking, on-screen interaction and full campaign qualification remain unrun.
