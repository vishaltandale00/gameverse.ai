# FireRed world source composition

`tools/whole_game/single_rom/world_assets.py` accepts isolated Emerald and FireRed source trees and an existing staged Emerald tree. It merges the full registered FireRed world: 425 maps, 43 groups appended after 34 Emerald groups, 383 layout slots (365 nonempty), all tilesets, object graphics and referenced field-effect graphics. Native Emerald group/map and layout positions remain unchanged. The importer never writes to either source tree.

Map constants become `MAP_FR_*`, layouts `LAYOUT_FR_*`, object graphics `OBJ_EVENT_GFX_FR_*`; map and layout names gain `FR`. Other donor constants and script/C symbols use `FR_`. The importer preserves every source map event and all connections/warp destinations and validates block/border byte lengths. Zero-sized donor borders retain their original bytes without inventing usable dimensions. Script/text composition is owned by the separate scripts importer.

`world-assets-ledger.json` records every map and assigned group/index, layouts and border dimensions, symbol translations, exact byte-copy SHA-256 provenance, source-header digests and unresolved responsibilities. A donor bank retains its original u8 object IDs. Raw u32 metatile attributes remain unchanged; generated designated Tileset initializers use the runtime extension `fireRedMetatileAttributes` and null native attributes. No truncation, substitute graphics or replacement maps are used.

Runtime compatibility is a separate gate. Source ingestion alone does not establish correct NPC/player graphics bank selection, field effects, animation callbacks, 640-primary-tile allocation, behavior/terrain/encounter semantics, border dimensions, hidden-item fields, state resources or campaign progression. The ledger stays `buildEligible: false` and `campaignComplete: false` while those responsibilities require integration evidence. No standalone combined ROM or complete-campaign claim follows from this report.

Four source-only unit checks cover the entire map index/topology, native index preservation, all copied-byte hashes, exact raw attribute pointers/graphics closure names, canonical source write rejection, deterministic repeat composition, and truthful qualification gates. `validation.json` records actual measured conversion/check duration and context. No build, dependency, CI job or broad simulation was added. A comparable previous-converter baseline is unavailable because this converter did not exist.
