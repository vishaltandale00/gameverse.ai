# FireRed battle-service roots

`stage_battle_services(base, donor, out, report_dir=None)` emits the remaining retail battle entry services into a fresh isolated Emerald tree. It must follow battle modes, encounters, Trainer Tower, native UI and world storage. `include/whole_game_fr_battle_services.h` is the typed interface shared with the separate Old Man controller and ghost-mechanics stages. Canonical decompositions and frozen build snapshots are never modified.

Thirteen of the fourteen battle-mode roots are implemented here. The shared-services resolver supplies the source-identical `FR_GetTrainerBattleMode`. Trainer defeat query/set uses the existing namespaced state helper. Introduction/cannot-battle speeches and rematch start retain original donor source bodies in `battle_setup.c`, with access to the actual shared native private battle state and already ported rematch callback. Trainer approach uses the shared native approach task and its real destroy/resume continuation. Encounter music calls the already region-routed native service, which selects the original donor grouping and imported tracks.

Old Man, Marowak/ghost and FireRed legendary identities use separate transient mode state. No FireRed flag is aliased onto Emerald's Wally, Two Opponents or Arena bits. The original Old Man entry creates a male level-five Weedle, locks field control and starts its source transition; the separate tutorial stage owns the complete controller, simulated input and graphics. The original Marowak entry respects Silph Scope, creates the specified female level-thirty Serious Marowak with fixed IVs when unveiled, records its source nickname and returns through the original defeat/result callback. The ghost stage owns ordinary Tower ghosts and the actual attack/capture/presentation rules. Legendary source species switches retain original Mewtwo, Deoxys, bird/Ho-Oh/Lugia and default music choices and transitions; its original AI flag policy is routed to the actual shared Emerald AI.

The Sevii e-reader house owns a separate original 188-byte card, supplied as an aligned 47-word saved bank by world services. FireRed's raw card class index must never be interpreted as Emerald's distinct facility-class index. The source record layout, checksum validation, invalid-card clearing, five-character name, class/picture lookup, party creation and farewell selection are preserved. Native graphics/name/class queries dispatch to that bank while the donor card battle is active. Native UI reads the same bank for greeting/name text, and provides its already source-exact character-count Easy Chat wrapping helper. The source-specific win/loss scripts avoid Emerald Frontier's extra speeches and generic money/whiteout behavior. The callback publishes the real battle outcome and returns to the original house script, which performs its original healing/restoration sequence.

`StartSpecialBattle` has three branches in the leftover R/S source. The importer proves that retail FireRed uses only selector two: every symbolic mention across donor data/ASM and C is counted; every direct special target must be registered; numeric/unknown targets are rejected; and the one actual house call has an uninterrupted `setvar VAR_0x8004, 2` lineage immediately before the call. This also catches the target when passed through a parameterized macro. Original selectors zero/one are archived rather than rebound to Emerald Frontier algorithms. The emitted provider's reusable typed input domain is selector two. An incompatible selector returns `0xFFFF` before constructing a party/task or claiming a battle outcome. The original full function and house script are retained with the ledger. All scanned inputs have an aggregate census hash; this proof must be re-established when donor source changes.

Three focused checks execute actual emitted source with explicit native-service fixture boundaries. They cover Old Man identity/party/transition, both Scope branches, legendary species music, statistic calls, valid/empty/corrupt e-reader cards, independent card size, invalid selectors, the three-mon card party and won/lost/draw callbacks. Additional cases reject a newly introduced parameterized-macro call and a numeric specialvar target. These are service tests, not native controller or campaign playthroughs.

Actual agbcc checks compiled seven affected C objects and the complete battle-script assembly on a private clone of the coordinator's retained diagnostic tree. The first pass found three integration mistakes: a missing item declaration, one unmapped private task name and a duplicate Easy Chat provider already supplied by native UI. Those were corrected; only the three changed targets were rerun, all passing. The untouched five targets retained their initial passing result. `targeted-compile.json` records timings, logs and object hashes. There was no ROM link or full build in this task. Initial and repaired compile durations are different scopes and are not a speed comparison; queue, ROM-build and gameplay durations are unavailable.

Source staging readiness does not certify ordinary-input Old Man/ghost/e-reader play or save/reload. Those checks remain with the coordinated integration campaign. `battle-services-ledger.json` records providers, source hashes, input-domain proof and exact remaining integration obligations.
