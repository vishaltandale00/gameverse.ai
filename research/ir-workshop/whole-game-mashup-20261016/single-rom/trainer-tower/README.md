# Retail FireRed Trainer Tower in the shared cartridge

`stage_trainer_tower(base, donor, out, report_dir=None)` imports the original Tower dispatcher, all 21 commands, all 32 source floor definitions, the four original eight-floor challenge tables, prize list, opponent speeches, class/picture lookup tables, timer/record rules and records board. Source-generated files are `src/firered_trainer_tower.c`, `src/firered_trainer_tower_sets.c`, their runtime/constants headers and a donor battle-script include. Run it after encounters, native UI and world services against a fresh staged source merge; it rejects canonical trees and accidental repeated staging.

Tower opponents come from the source's encoded `BattleTowerPokemon` pools, selected by the original single/double/knockout floor tables and scaled to the highest non-egg party level. They do not use the ordinary 4096-offset trainer namespace. Both decompositions' 44-byte `BattleTowerPokemon` field layouts are checked directly before importing. Native Emerald creates the actual Pokémon and executes battles; no Battle Frontier roster or challenge algorithm replaces Trainer Tower.

FireRed's Trainer Tower battle bit collides with Emerald's Factory bit. A separate `FR_IsTrainerTowerBattle()` mode therefore selects the donor custom roster, name/class/pictures, win/lose speeches and source victory/loss scripts. Common native-engine guards retain Tower's no-experience, no-generic-prize-money, no-Pokédex-registration and item-steal/Trick restrictions. Original Factory/Frontier bits and records remain unchanged. The Tower battle callback clears the mode when returning to the source field script.

Object graphic IDs become 16-bit in the transient Tower NPC-selection tables because imported graphics can exceed the donor's eight-bit namespace. Donor facility indices remain original, while their picture/class lookup results point to the imported donor graphics/classes. Every Easy Chat word used by the roster is checked to retain its original packed group/index before using the shared native word renderer. The native UI stage supplies actual donor frame graphics through `FR_LoadStdWindowFrameGfx`; the Tower does not invent an alternate records interface.

World services owns the one persisted 52-byte Tower extension: four original 12-byte records and the challenge ID. Best times retain source XOR encryption and native save-key rotation. A separate VBlank timer index locates the selected live saved record on each tick, preserving the original counter semantics without retaining a pointer across native PC-buffer relocation. Original timeout checks, once-only reward flags, floor completion and loss acknowledgement remain source functions.

The retail FireRed source explicitly disables external e-reader set selection: `ReadTrainerTowerAndValidate()` is an original `return FALSE` stub with the comment “Stubbed out. Populated in Emerald.” The importer verifies and preserves that body and the resulting original local-floor fallback. This is a documented original feature state, not an invented successful no-op or fallback hiding an unported service. The retained read/validation closure performs no flash writes; no native save sectors are reassigned, and external e-reader support is not claimed.

`trainer-tower-ledger.json` records source hashes, all emitted files, provider symbols and integration dependencies. Its source-stage readiness does not claim a completed ROM build or a played Tower campaign. Coordinator compilation, native save/reload, UI/battle transition checks and ordinary-input completion remain necessary.

The focused checks compare deterministic transformations and execute actual emitted C functions across every floor and single/double/knockout party selection, highest-level/egg handling, full-bag reward rejection, once-only rewards, encrypted best-time updates, loss acknowledgement, owner state and timer start/stop. External Pokémon creation and bag capacity are controlled fixture boundaries; no full native battle or UI is claimed by those tests. Timings distinguish source transformations, fixture compilation/execution and enclosing test wall time. Nested durations must not be added again. No previous Tower importer baseline exists, and no turnaround speedup is claimed.

The coordinator's first real compile exposed three ABI bindings that the source-only fixture did not cover: donor object constants/text-color declarations and the donor recall-mask battle subcommand. The importer now includes the donor constant/state headers and ports the original recall-mask handler as native Various subcommand 27 (unused in Emerald, whose original range ends at 26). Donor recall macros lower to native macros with an explicit attacker operand; their existing native handler bodies match the original donor behavior. The focused C fixture covers every two-opponent live/fainted mask and the single-opponent boundary.

The repaired Tower translation unit, native battle-command translation unit and complete battle-script assembly passed actual agbcc/ARM assembler checks on an isolated clone of the coordinator's retained diagnostic tree. The original snapshot was untouched. A subsequent Tower-only incremental compile after removing a redundant macro definition took 0.511 seconds. The initial three-object check's wall time was not instrumented and remains unavailable.
