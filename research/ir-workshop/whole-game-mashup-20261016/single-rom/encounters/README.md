# FireRed encounters in the single Emerald cartridge

`tools/whole_game/single_rom/encounters.py::stage_encounters(emerald_source, firered_source, output_tree, report_dir=None)` transforms an isolated Emerald tree. Canonical source trees are read only. It needs no network, new dependency, toolchain setup or ROM build. The generated translation unit is picked up by Emerald's existing source wildcard.

The importer preserves 742 ordinary donor trainer records and every original party; donor NONE remains native sentinel zero and its empty duplicate record is omitted. Ordinary IDs are 4097–4838. Native special trainer IDs remain unchanged. All 148 original front pictures, palettes, animation selections, 107 class names and original prize factors are appended under a donor namespace. The sparse trainer array is deliberate; no trainer identity lookup service is substituted. Native recorded-battle apprentice array accesses now have an explicit upper bound.

The cartridge uses the actual Emerald party, battle, AI, capture and evolution engine in both regions. Trainer AI flag **symbols** retain their meaning when compiled against Emerald: FireRed's viability/try-to-faint bits are reversed relative to Emerald, so copying numeric masks would be wrong. Donor trainer gender, names, items, party species/levels/IVs/moves and original scripts retain source values. Only three AI flags occur in the donor trainer table, and all three have native Emerald semantic counterparts. This is an explicit composition policy, not an algorithm-equivalence claim.

All 132 FireRed wild headers (124 distinct maps, including nine Altering Cave alternatives) are merged into the native header array. All 113 land, 50 water, 50 fishing and 14 Rock Smash tables retain exact rates, slots, species and level ranges. The alternate 132 LeafGreen headers are inactive, matching a FireRed build of the original donor. FireRed's complete wild source dispatcher is emitted as `src/firered_wild_encounter.c`: original cooldown, rate buffer, LCG, repel, flute, Cleanse Tag, Stench/Illuminate, level/nature generation, Tanoby unlock/Unown letter generation, Altering Cave variable selection, Sweet Scent, fishing and Rock Smash all remain original source. Native entry points dispatch by current region. Raw 32-bit donor metatile attributes are consumed through the map semantics provider, without interpreting Emerald's terrain encoding as FireRed's.

The runtime header is `include/whole_game_fr_encounters.h`; constants live separately in `include/constants/whole_game_fr_encounters.h`. Field movement calls `FR_TryStandardWildEncounterAtPlayer()` before Emerald's immunity-step prefilter, and campaign initialization seeds `FR_SeedWildEncounterRng(Random())` once. World services supply the independent donor roamer. Native shared repel duration and flute flags apply to both regions. Repel countdown uses native Emerald code; the donor quest-log-playback suppression is excluded because this composition does not run donor quest-log playback. Fishing increments FireRed's separately saved statistic using its source constant, not Emerald's differently named statistic at the same numeric slot.

434 donor item names/aliases resolve by semantic symbol to existing Emerald item IDs, including machine move aliases. Original donor item metadata is retained in the staged tree. Regional pricing uses the complete original donor price table; this preserves the real Retro Mail price difference (FireRed 50, Emerald 0). Script imports preserve original shop stocks, gifts, prize choices and source item quantities. Bag-use callbacks and special shops remain dependencies of the world services, native UI and script stages; item IDs alone do not claim those services work.

New Pokémon record `VERSION_FIRE_RED` when created in Kanto and retain the source's raw eight-bit met location. Hoenn creation retains Emerald origin. Existing Pokémon are not rewritten. The UI resolves overlapping region names from origin version and recorded met location, rather than the player's current region.

`encounters-ledger.json` pins every source input and lists concrete integration requirements. `build_ready` means this source transformation completed without unmapped data; it does not certify compilation, gameplay, campaign completion or save compatibility. Coordinator compilation and native qualification remain required. In particular, the world-services provider owns source Safari bait/rock rules, independent roamer state and special key-item use; native UI owns donor bag containers. Native Frontier's ten-bit records remain restricted to native facility trainers.

The focused test checks exact donor wild rows, trainer namespaces, item aliasing, semantic AI flags, original graphics references, origin metadata and byte-identical repeated staging. A tiny C fixture executes actual emitted source for Tanoby locked/unlocked admission, all Altering Cave boundary choices, unknown-map rejection and raw attribute masks. It is not a full ROM build or a gameplay simulation. The fixture initially caught accidental namespacing of `MAP_GROUP` and `MAP_NUM`; that failure and the earlier idempotence failures are retained in `verification.json`.

Timing uses monotonic stage/test timestamps. The verification receipt distinguishes two comparable transformations, fixture compilation and fixture execution, all nested within test wall time; those times must not be summed into a separate run total. Queue, full ROM build and gameplay time are unavailable, not zero. There was no prior single-ROM importer baseline, so no speedup is claimed.
