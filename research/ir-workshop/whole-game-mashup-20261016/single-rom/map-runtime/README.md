# Single-ROM map and object presentation runtime

`tools/whole_game/single_rom/map_runtime.py::stage_map_runtime(emerald_source, firered_source, output_tree, report_dir=None)` patches an isolated staged Emerald tree. It rejects canonical trees and descendants. It consumes the world-assets import and the state namespace; `map_semantics` must subsequently provide `WholeGameFireRedBehavior`.

The patch preserves the donor's full 32-bit attributes through a trailing `Tileset.fireRedMetatileAttributes` pointer. All eight fields remain queryable; the Emerald attribute pointer stays null on donor tilesets. Donor tileset designated initializers must follow Emerald's callback/attribute field order. The primary metatile and tile splits are 640/384 on donor layouts and 512/512 on native layouts; the palette split is 7/6. Fieldmap upload paths, camera rendering and shop rendering use the layout's origin. Attribute behavior dispatch belongs to the separate semantic consumer stage, rather than a truncation or same-name substitution.

`MapLayout` has trailing border dimensions and mapjson emits them for both source domains. Border sampling preserves phase `(x-7,y-7)` and supports negative coordinates. Donor zero-dimension layouts are unused by all 425 registered donor maps; they remain unadmitted, with no invented border data.

Saved object graphics IDs remain eight bits. Native callers carry a transient ninth bank bit only through presentation APIs. Objects select their bank from their own map group and local ID, keeping the native player in the original bank while donor NPCs use the complete imported bank. Donor dynamic IDs read the donor variable namespace, including eager object initialization. Object effects, shadows, reflections, shop portraits, respawning and graphics changes retain this provenance. Virtual objects retain the bank in `Sprite.data[7]`, unused by their existing callback, and script creation supplies it explicitly.

Donor palette tags occupy a disjoint range (`original + 0x2000`), and exact donor registry rows and reflection pairs are merged into the native lookups. Default NPC palette slots select donor colors on donor maps; native player palette slots remain native. This fixes the separate palette problem that a graphics pointer bank alone cannot solve.

Four focused tests pass; two compile and execute the emitted C helpers. The probes cover the 639/640 metatile boundary, full attribute extraction, 512/640 and 6/7 splits, native player versus donor NPC, the native Bard ID collision, donor versus native dynamic variable resolution, invalid donor IDs, palette namespace, virtual bank retention and deterministic patches. Canonical input bytes are checked unchanged. See `verification.json` for measured total time, source pins and retained failed fixture attempts. This is a new suite, so no comparable earlier duration exists. Compiler subprocess times are not separately measured.

These checks do not qualify a complete game. The ledger deliberately blocks semantic admission until the separate predicate/terrain/encounter consumers, tileset animation source linkage, standalone graphics providers and native compile/render checks establish their claims. No ROM build, browser, model call or gameplay simulation was run by this module's checks. `map-runtime.json` is an isolated source-patch fixture receipt, not a combined build receipt.

## Actual compiler repair evidence

`targeted-agbcc.json` records successful compilation of `event_object_movement.c`, `firered_region_map.c` and `firered_map_preview_screen.c` with the existing agbcc flags. Work used a private copy-on-write clone of failed build `20261016T171250Z-eb5bd6a023b8`; neither its frozen source nor canonical decompositions were edited. The first targeted attempt took 1.8133 seconds and retained its errors; the remaining two affected units passed in 1.0506 seconds after generator fixes. Preview compilation had already passed and was not repeated. Asset cache state and scope differ between attempts, so these are repair timings, not a speedup comparison. Seven combined focused checks pass in 0.380 seconds.

The fixes preserve actual source bytes and indices: nested graphics includes use sibling paths, donor animation constants are imported, the preview uses the native `field_screen_effect.h` declaration, `DPAD_ANY` keeps donor bytes `F8 0C`, JSON labels follow UTF-8 byte iteration, map pairs expand to the shared group/number macros, and the repeated-key macro reads the same source field. Linking and native UI/gameplay execution remain unverified.

The subsequent VS Seeker/Fame Checker integration adds an explicit transient player graphics-bank override, reset by `ResetObjectEvents`, and the exact donor `FR_CreateFameCheckerObject` source helper inside the native object translation unit. This preserves donor VS frames without changing player/map IDs. The effect owner must disable the override before native restoration on every exit path. The new object TU passed actual agbcc compilation in 1.3120 seconds; the unchanged region/preview units were not repeated. The updated four-check module suite passed in 0.259 seconds.

Fame Checker now calls explicit `FR_InitFameCheckerObjectPalettes(u8 reflectionType)` rather than inferring the palette bank from the current map. It uses the shared original initialization lifecycle and the donor NPC/default reflection arrays, with native player slots retained. The affected object TU passed agbcc compilation in 1.2724 seconds. Four updated module checks pass in 0.205 seconds. The region provider preserves the full Quest Log owner's constants header when present, and its fallback imports every macro name plus the playback-state reference; its three focused checks pass in 0.192 seconds.
