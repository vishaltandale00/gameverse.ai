# Bounded effect shape evidence

`tools/whole_game_composition/effects.py` scans supplied L1 bodies and optional validation adapters. It does not disassemble ROMs, resolve SSA pointers, execute games or invoke models. These records are candidate search hints and contradiction evidence, with no change to qualification, readiness or behavioral compatibility.

Run focused checks with `python3 -m unittest tools.whole_game_composition.test_effects`. Four checks use existing local IR packages and explicitly skip if private fixtures are absent; two use small synthetic unknown/hardware examples. The initial six checks passed locally; three additional authored overlay identity/provenance checks also pass (nine total). No dependency, build or CI stage was added: this check covers cheap access extraction and rejection logic only.

`examples.json` binds four actual packages by behavior and adapter SHA256. The artifact contains metadata and effects, with no compiled payload or asset data. Source comparison:

- FireRed timed acknowledgement: the existing package source contract identifies argument-relative `field_0` at offset 22 and a read-only selector at `0x0203adfa`. The summary preserves the first address as unknown and recovers the second from the adapter's explicit base-zero plus offset encoding. It does not convert invocation counts into video frames.
- Zero Mission events: the retained decompiler analysis oracle `research/ir-workshop/source-game-prefabs/metroid-zero-mission/080608bc.c` accesses a uint bank at `0x02037e00` with four-byte layout and conditional bit writes. L1 plus adapter recovers read/write EWRAM, four-byte width/element stride and capacity eight. This oracle is analysis provenance, not recovered original source or compiler input. The classifier deliberately leaves the dynamic index bound unproven.
- Crash direction lookup: source-contract metadata describes sampled input and a direction table; the existing IR has a 16-byte immutable asset. The summary proposes `bounded_table_lookup` but does not infer a direct hardware input read or prove index safety.
- Aria horizontal integration: source annotations identify position/velocity/acceleration. The classifier only proposes field update shape, preserving unknown physical addresses. Its similar update shape to FireRed does not imply substitutability.

The examples demonstrate three known contradictions for Zero Mission: eight-byte required stride versus four-byte layout, IO destination versus EWRAM, and read-only requirement versus explicit writes. A constant-index requirement with a dynamic expression returns unknown, because the expression might simplify or have a separately proven domain. `element_stride_bytes` is declared storage layout, not traversal stride. `capacity` is storage capacity, not invocation or transfer count. Each access record is a static syntactic occurrence, not a dynamic execution count. Pointer chasing and aliases remain unknown.

`compare_effect_constraints(summary, {"objects": [{"name": "collection_0", "space": "EWRAM", "element_stride_bytes": 4}]})` returns `shape_constraints_satisfied`, `unknown` or `contradicted` with reasons. Empty requirements return unknown. Even satisfied shape constraints leave behavioral compatibility unproven. `query_effects` matches individual object properties and candidate patterns; `writes=False` means at least one read-only object, not necessarily a wholly read-only component.

Measured static summary costs for the same four pre-parsed inputs are approximately 0.055–0.160 ms per component on this host, with context in `examples.json`. Parse/setup time is excluded. There is no prior summarizer baseline, so no before/after improvement is claimed. Build, simulation, evaluation, queue and source commit measurements are unavailable/not run. Behavior and adapter hashes identify the actual inputs instead. No numeric performance budget was introduced.

`import_behavior_overlay(game, behavior, bindings=None, provenance=None, component_ids=None)` attaches a `behavior:<package_id>` node, falling back to the IR ID if no package ID is supplied. It requires `source_game` and pinned `{path, sha256}` `behavior_ref`/`package_ref` provenance; the caller verifies raw-file pins before parsing. A separately recorded canonical parsed-IR hash preserves parsed identity. Optional adapters require their own pin. Nodes remain native-component scope with unknown native effects and closure; no claims are upgraded. Without explicit component IDs the node stays unplaced. Explicit IDs must name existing canonical component refs and carry `component_mapping_evidence`. Raw source contract references can be supplied in `source_contract_refs`; the helper retains them without inferring their authority.
