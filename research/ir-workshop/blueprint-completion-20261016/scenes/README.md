# FF I/II choice-scene closure audit

The original source establishes a coherent scene-object path: wrapper `0801d490` allocates and constructs one scene, `08014938` executes entry/fade/loop/restore phases, `0801d074` opens phase-7 choice navigation, `0801d100` handles A/B and directions, and the wrapper copies the result before `0801d40c` destroys the scene. [closure.json](closure.json) pins the roles and source evidence. The choice scene is a source-backed partial route for `dialogue-interactive-scenes`; original dialogue text/content has not been identified in this route.

Executable evidence is narrower. `ff12.choice.entry_transition` has a published source member and 256 retained original/native parity cases. The `0801d338` context-restore leaf has 256 retained parity cases but is private. The existing choice-entry Composer assembly validates bindings and lowering; it does not execute the full scene. The retained native fixtures use synthetic state, not actual gameplay traces.

The [current six-target automatic-lift probe](lift-probe.json) blocked navigation (`0818c250` callback), the scene loop (unproved jump-table remapping), destructor (`0818c260` callback), wrapper (`0818c250` callback), subobject cleanup and base cleanup. It ran no native vectors because none of these roots lowered. The probe used one ROM read, six L0 inputs, no JVM/export, no compiler/catalog edits, no new game and no prefab registration. It measured 0.045 s total on this host; queue time is unavailable. Prior native stage times are retained in their original receipts, with no comparable before/after run available.

[Original ROM veneer and literal verification](veneer-witness.json) resolves two exact callsite targets: `0818c250` is `bx r1` and the navigation caller loads `0818abfd` (real `0818abfc` feedback), while `0818c260` is `bx r5` and the destructor loads `08015271` (real `08015270` subobject cleanup). Base cleanup is `0818c254` (`bx r2`) with `08014a91`. The six target/caller L0 exports are pinned. These generic veneers cannot be treated as returns: callsite specialization needs original register/LR proof and the nested audio/resource services. The compiler owner confirmed that specialization is viable in principle but outside the current shared scope.

The smallest next closure is the actual `0801d100` navigation feedback callback with shared pressed-edge input, followed by the real `0801ca98` phase-10/11 loop and `0801d490` result/destructor. The allocator, fade, render/audio, IRQ wait and nested cleanup services must be explicit original or versioned native-host invocations. The current native oracle calls a single function for at most 2,048 instructions; the original scene loop also needs initialized input/audio/IRQ/heap state and a frame scheduler. A direct isolated wrapper call would not establish a playable scene. A fabricated dialogue line, substitute choice algorithm or no-op service would not close this blueprint.
