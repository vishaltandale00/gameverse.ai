This packet narrows the missing discovery → ownership → benefit → commit path for the existing `tmc.learned_sword_charge_release` blueprint. It supplements the canonical [progression system](../../game-system-assembly-20261016/progression/system.json) and [Minish prefab delivery](../../../deep-extraction/resume/legend-of-zelda-the-the-minish-cap/prefab-pass/delivery.json); it introduces no new blueprint, authored behavior, or readiness claim.

The apparent world pickup route at `0x08081420` is **not** a proven first-time technique grant. It calls `0x08053ff0` only when `0x08081450` returns zero. That predicate returns true for a zero learned-state getter or metadata flag bit 1. Original ROM table flags are `0` for ID `0x48` and `2` for ID `0x73`. Thus the route does not prove a fresh grant of either technique; `0x73` is blocked by the flag in this branch. Other callers of `0x08053ff0` exist, but their item identity and one-time claim semantics are not tied to these technique IDs. `0x0807f078` is a generic script setter, not a recovered trainer script.

The parser evidence implies a three-halfword opcode `0x0c85` for this command. An exact raw-ROM scan found no `0x0c85,0x0048,0x0001` or `0x0c85,0x0073,0x0001` sequence, nor those payloads under any other top-six-bit length with opcode `0x85`. This does not rule out generated or loaded scripts. It prevents attributing a specific original trainer grant to this command on current evidence.

The smallest remaining source closure is to identify the original trainer/script or reward actor that grants `0x48` (and later `0x73`), prove its once-only claim and refresh order, and qualify the accepted external-media save/reload path for this bank. The separate `0x08075580` call ABI and subsequent actor services still block automatic action closure. Until these are proven, progression remains partial.

`source_routes.py` reads the retained corpus and original ROM, verifies the direct call edges and dispatch pointer, and writes `source-routes.json` with exact hashes. One permitted Ghidra export produced [L0](../../../../local/ir/fleet-next/legend-of-zelda-the-the-minish-cap/script-command-ex050/l0/0807f078.json) in 4.315695 seconds with the original project unchanged. The first lift failed on nested input-pointer resolution (`unresolved pointer v4`). A scoped compiler fix subsequently recovered [automatic L1](../../../../local/ir/blueprint-completion/minish-script-static01/l1.json), validated and lowered it, then passed [512 native parity cases](../../../../local/ir/blueprint-completion/minish-script-native01/receipt.json) in 0.311816 seconds, covering the full packed bank and cursor/context canaries. The caller-scoped void state-effect view is now published as `tmc.progress.script_inventory_write`; residual original `r0` is outside its contract because the parser overwrites it before use.

The [actual Composer graph](script-learning.assembly.json) binds two instances of that published script command and one `tmc.progress.derive_skills` instance to a **single shared 64-byte inventory bank**. It invokes command `0x48` → refresh → command `0x73` → refresh; [validation](script-learning.validation.json) passes with `binding_valid_obligations_unproven`. The [generated C](script-learning.core.c) compiles, and [host checks](script-learning.check.json) pass state-0 no-change, first and repeat state-1 writes, states 2/3 rejected as learned, neighboring-slot preservation, explicit refresh boundaries, and final skill mask `0x201`. The graph/check run took 0.207348 seconds. These are legal caller-supplied operands for the recovered command, not a recovered interpreter stream or trainer encounter; the handler does not validate opcode or advance its cursor. `source_order_learning` is an explicit illustrative schedule, while the original source relationship only pins handler-to-setter and player-init refresh separately.

The [native proof](../../../../local/ir/fleet-next/legend-of-zelda-the-the-minish-cap/script-native-04/report.json) invokes the **original** script handler with a real cursor layout for eight cases, including repeat writes, states 2/3, fast-skill state, and neighboring slots. It then calls original refresh explicitly. All eight pass. One further case calls the original ROM DMA helper with the `0x4b4` callsite extent to copy the live save structure into a slot buffer, clears learned state through the source setter, restores the slot, and refreshes again. Observed state is `1→slot 1→live 0→live 1`, with skill bit 0 restored. The run took 0.168786 seconds; its first two expectation failures are retained in `script-native-01` and `script-native-03`. This proves the native command and slot memory behavior, not normal script dispatch, disk/flash persistence, or portable composition. The corpus is a decompile census, so indirect calls may be absent from caller lists.
