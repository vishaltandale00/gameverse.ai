## Runtime and presentation

`src/playable-mashup-runtime.js` imports each candidate's actual `createCandidate` adapter, advances `step(rawHeldActions)` at a bounded authored 60 Hz, and draws `observe()` state. It does not implement damage, terrain, progression or outcome. Both final adapters instantiate actual compiled recovered/generated C as WebAssembly, with no JavaScript fallback. Authored JavaScript owns the world, scheduler and game orchestration. Candidate owners retain exact C/WASM pins and differential evidence; the initial translated-JavaScript prototype was superseded after the actual compiler was supplied.

Keyboard, on-screen pointer/keyboard controls and existing standard-gamepad sampling feed the same adapter. Pause stops simulation; blur/hidden-page pause clears held input; restart works in all phases. A six-step frame cap prevents unbounded catch-up. Each candidate owns action edges, confirmed identities, world geometry, phase and its reset. The HTML gives textual objective/status, labeled controls, keyboard focus and resize through a fixed-aspect responsive canvas. Textual fallback is not a complete screen-reader equivalent of a spatial action game.

Relay Runner uses an authored side-view camera clamped to its 1760×480 world. Visible platform/gate/hazard geometry comes from the simulation snapshot. The authored courier anchor is bottom-center, and the debug collider is the candidate's 20×28 body. Attack arcs and accepted-hit rings bind actual action/contact state; the HUD reports actual HP, cores and Air Step. Scenery, courier, ruins, beacon, materials and effects are authored canvas graphics. No recovered background-map/collision closure is claimed.

Echo Tactics uses an authored oblique arena with fixed battle positions, original Pokémon walker sheets and original recovered Metroid Ripper metasprites. Its combat uses candidate state, not drawn board coordinates. Target ring, enemy health/intent, focus, learned abilities and recent combat log follow actual observations. On-screen actions disable with unavailable capabilities; raw keyboard actions still reach the candidate's explicit denial path. Projection, arena, position binding and target ring are authored. No Pokémon/Metroid game recreation, source-native palette ownership or native camera parity is claimed.

## Asset closure and privacy

`prepare_assets.py` reuses only two source PNGs plus retained MZM Ripper tiles/palette/OAM/scripts. It does not inspect ROMs or run new extraction. It creates RGBA index-zero transparency for the 144×32 Red/Brendan sheets and packs all five Ripper frames at the original OAM origin (48,32), preserving piece offsets and flip flags. Ripper idle uses recovered 0,1,2,1 at 16 ticks each. Authored actor scaling and bottom-center walker anchoring are not recovered foot pivots.

Private outputs remain ignored under `local/playable-mashups/assets/`. `manifest.json` records source SHA256, output SHA256, recovered scripts and authored conversion/anchor statements. No copyrighted pixels were copied into tracked files. `scripts/playable-mashup-assets.mjs` grants four exact media paths plus two exact candidate WASM paths (application/wasm); server retains workspace realpath confinement. There is no arbitrary local file route. Assets are intentionally absent from the public shell build. Missing private assets fall back to authored shapes.
