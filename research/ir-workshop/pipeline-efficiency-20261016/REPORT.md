# Pipeline efficiency investigation — 2026-10-16

The primary bottleneck is the unit of work and its acceptance criteria, not native execution speed. The pipeline can turn selected functions into exact, bounded symbolic programs. It does not yet reliably turn a player-visible responsibility into a closed executable subsystem. More function-level successes consequently increase the catalog without necessarily reducing the missing controller, terrain, scheduler, resource, rendering or persistence obligations. Function lifting is useful as a compiler implementation unit; it is the wrong default planning and delivery unit.

This audit used current code, retained original-source exports, qualification receipts and completion packets. It ran no game generation, emulator campaign, paid model call, Ghidra export, build or CI. Concurrent workers may advance publication after the pinned snapshots below. The current snapshot reports 127 packages, 123 unique original roots, 103 typed-port subsets, 22,851 bounded L0 exports, 2,351 static candidates and 835,091 retained fixture pairs. The blueprint frontier still reports nine blueprints and 42 required responsibilities, with zero complete blueprints. These denominators are different: dividing packages by L0 exports would not measure subsystem yield or ROM coverage.

## What the current IR actually does

`tools/behavior_ir/lift.py` consumes HighFunction p-code SSA, not pseudo-C or an LLM-written reconstruction. It converts supported control/data operations to exact symbolic integer behavior. `bounded_cfg.py`, specialization and range analysis admit bounded loops/control paths; state, arrays/assets, parameters and supported calls become explicit structures. The validation adapter retains original machine layout and ABI. L1 removes native locations from public semantics but retains source integer widths/wrap, branch behavior, table values and constrained source effects. `lower.py` emits code; `qualify.py` compares emitted execution with the original CPU on finite synthetic/boundary or explicitly supplied causal inputs.

That is a valuable low-level portability foundation, not a general gameplay model. Unknown units/frames, invocation timing, canonical actor identity, actual input admission, source assets, indirect dispatch and service effects do not become understood merely because instructions lower. Native finite parity is neither reachability nor lifecycle completeness. The default oracle limit of 2,048 instructions per call is appropriate for many leaf probes but does not establish a running scene with heap, interrupts, audio and frame scheduling.

`assembly.py` correctly reports `binding_valid_obligations_unproven`: exact package pins, types, frames, ownership, domains, ordering and generated lowering can be checked without proving that the schedule is the original schedule or that the assembled system plays. Cross-game adaptation is sometimes necessary and must remain visibly authored. The DB input→explicit bit map→Minish consumer is a useful bounded composition, not proof of original DB physical button semantics or a complete game.

## Where work is lost

1. **Discovery optimizes candidate availability.** `pipeline.py` exports bounded per-ROM candidates and stops at `depth_pending`; `mine_input_frontiers.py` selects eight leads using hardware-input textual references, branches and assignments. `depth.py` has real recursive callee closure, but it starts from function profiles. Neither establishes the full state/lifecycle boundary first. Spreading extraction across 33 titles delivers breadth while leaving several indispensable responsibilities missing in every blueprint.
2. **Complexity accumulates at exactly the useful boundaries.** FF I/II's wrapper crosses register veneers, indirect destruction, allocation, fade, IRQ and input scheduling. SMA1 retry needs world re-entry and fixed-point position rehydration after a valid retry leaf. Minish script setter and refresh work, while the actual trainer/once-only claim and durable-media commit remain unidentified. These are missing source understanding or runtime providers, not just missing metadata labels.
3. **Backend repairs repeatedly rediscover classes.** Evidence identifies erased call arguments/non-AAPCS registers, loop/phi/structured-expansion blowups, pointer alias ownership, nested references, callback veneers, and unknown services. Repair the class with a pinned positive fixture plus adjacent negative fixtures, then invalidate/retry all affected blocked roots. Do not request a new isolated workaround for every leaf.
4. **Readiness naming encouraged the wrong count.** At inspection, `depth.py` set `closure_ready = ports_ready`; `ports_ready` could mean any known scalar quantity or a public collection. `snapshot.py` separately derived mechanics closure from typed ports. This does not match blueprint closure. The compiler owner implemented the distinction; final focused verification and independent source review are clear (see final updates below).
5. **Incremental invalidation was incomplete.** `depth.py`'s fixed compiler-signature tuple omitted imported helper modules including bounded CFG, pointer-region and entity-reference logic. An unchanged blocked row could stay skipped after the repair that should unblock it. The compiler owner implemented transitive static local-import fingerprints, missing-file visibility and retry regression checks; review also closed fixture-content and qualification-runtime invalidation gaps.
6. **Publication and consumption require repeated hand translation.** Producer annotations, return semantics, alias evidence, metadata overlays, reviewed package copies and consumer re-pins are distinct handoffs. Mutable `local/ir/packages/<id>` manifests stale downstream pins. MZM's frozen alternative branches are valid but the one-game delivery registrar reports a merge conflict with an existing game delivery. Versioned immutable package identities and a deterministic delivery merge would reduce this friction without weakening review.
7. **Coordination latency is not measured.** Worker handoffs and changing UI scope are reported contributors, but no reliable wall-time ledger proves their share. Repeated messages to completed workers cannot be quantified from filesystem stage receipts. Native/export milliseconds cannot be summed and called end-to-end latency.

## The better delivery unit: a source behavior capsule

Start each job with one observable responsibility and a same-source entry→effect→cleanup episode: e.g. accepted attack through reaction and retirement, or scene choice through result and teardown. Recover a bounded execution region, not the whole game and not an arbitrary list of functions.

Its packet should contain: exact ROM/export/ABI identity; entry phases and reachable input domains; call and dispatch graph; state read/write/alias ranges and canonical owners; source ordering/clock; assets and service providers; outputs and termination; scenario obligations; proof status; and explicit cut edges. LLMs can propose subsystem boundaries and contract meanings from a retrieved source neighborhood. Deterministic graph/layout checks and original execution must validate those proposals. Same-address data references are useful discovery hints, not proof of compatible meaning or ownership.

Construct the neighborhood from callers/callees, resolved dispatch targets, shared state and effect dependencies. Cluster by lifecycle and strongly connected call regions, then cut at explicit, versioned services. Do not automatically absorb every shared-global neighbor: ubiquitous input/audio globals would merge the entire game. Separate structural candidates from instruction-verified edges and observed execution paths. A missing indirect edge must remain a blocker even if the direct-call graph has no open cut.

Use three honest execution categories:

- **Portable capsule:** all relevant behavior lowered, shared state explicit, providers implemented and qualified; source scenario and generated-host scenario agree within declared limits.
- **Mixed capsule:** portable region calls an explicit original/native service. Require shared backing, pointer/ABI marshaling, observable side effects, deterministic clock, snapshot/restore and cleanup. If these cannot be supported, the boundary is blocked. No no-op audio/resource stub silently replaces source behavior.
- **Original-engine capsule:** a version-pinned emulator/source runtime and initialized savepoint execute the source subsystem. This can deliver larger faithful behavior sooner and provide reference traces. It retains ROM/runtime/service dependencies and generally cannot be freely transplanted into another game or target. It is a reference/provider intermediate, not portable IR.

Compiling decompiler pseudo-C wholesale is not an automatic escape hatch: missing types, hidden registers, volatile hardware, pointer aliasing and broken indirect calls remain. Where genuinely editable, reproducible source already exists, source-level encapsulation can be cheaper than reconstructing everything through IR; record the different provenance and portability contract. Do not handwrite guessed recovered logic.

## Reuse and extend the machinery already present

`depth.py` already recursively closes calls and caches source/profile/compiler signatures; it can reuse unchanged C/ROM/adapter/oracle/fixture qualification. `publish_intake.py` already batches pinned metadata and avoids re-running native proof for unchanged executable content. `causal.py` already accepts correlated expected states. `trace_fixture.py` already maps saved RAM into fixtures, although its existing Sonic samples explicitly are end-of-phase snapshots, not function-entry traces. `scripts/register-game-system-deliveries.mjs` already validates and snapshots deliveries. Extend these paths rather than creating a second orchestrator.

The next trace step is generic, source-pinned function-entry/exit capture with source frame, event identity, canonical object/pool identity and full admitted state. Feed correlated snapshots to the existing causal loader; replay negative cases for interruption, duplicate events, stale handles and reset. Preserve unobserved branches as unproven. A frame screenshot hash is not a semantic state identity.

`tools/playtester` already provides System 1 Decisions selection, System 2 constrained escalation, deterministic target continuation, budgets and retained transitions. The native session bridge advertises checkpoint/restore and accepts initial save states. The controller adapter exposes observe/act/close, not public checkpoint/restore orchestration. `tools/gba_playtest/scenario.py` already replays version-pinned native save states with semantic expectations. Do not build another bot or scenario runner. When game generation resumes, add capability-gated checkpoint forwarding and a phase/invariant scenario adapter using these paths; trigger model decisions at meaningful junctions and `requires_decision`, not every frame. First verify restore-equivalence, unsupported capabilities, budgets and cleanup offline. Then separately authorize a bounded original/candidate pilot. Static correctness, finite native parity, semantic scenarios, playable completion, and enjoyment are five different acceptance levels.

## Implemented in this audit

`capsule_frontier.py` provides a standard-library-only bounded planner over retained JSONL exports. It records deterministic call neighborhoods, missing/direct cut edges, unresolved function-pointer candidates, decompiler/indirect-control hints, shared-RAM/caller context candidates, source/tool hashes, and a bounded argv for the existing `expand.py`. It never executes the job, changes central catalogs, or labels graph coverage executable. Known L0 filenames are only an inventory hint; its job explicitly requires reconciliation of other retained exports and the existing export-owner resource lease before execution.

Four focused tests pass: cyclic/shared dependency traversal; missing calls/services versus pointer candidates; caps/cache/context distinction; and invalid/missing roots. Actual Minish and FF I/II runs are retained in `*-frontier.json`. Minish selected 32 nodes, seven cuts, and 17 L0 entries absent from the supplied inventory; FF I/II selected four direct nodes, zero direct cuts, three pointer candidates and three entries absent from supplied inventory. The latter is a concrete demonstration of why call-only closure is insufficient. No corpus was exported again. This is a tested first planning stage, not a claim to have automated semantic extraction or improved full-game throughput.

## Prioritized rollout and measurable acceptance

1. **Fix retry/readiness now** through the existing compiler owner. A helper-only change must retry affected blocked work; unchanged dependencies must not cause native reruns. Distinguish typed primitive, source dependency closure, composed scenario closure and full subsystem closure everywhere.
2. **One complete capsule pilot, plus a small contrast case.** Choose from the existing closure matrix by remaining dependency cost, not title coverage. Minish still has unknown reward identity/durable persistence; do not assume its new setter automatically makes it cheapest. Compare source-obligation paths before committing. Use frontier output to batch missing evidence once; a semantic owner fills the capsule contract and compiler/provider owner handles shared repairs. Freeze user-interface expansion during this pilot.
3. **Automate the handoff.** One immutable packet derives semantic manifests, generated host bindings, scenario inputs and delivery registration from canonical state/port records. Independent review approves the evidence and contract once; downstream artifacts are generated and exact-pinned. Add a deterministic append/merge for compatible same-game deliveries. Preserve conflicting versions explicitly rather than overwrite.
4. **Repair queue by affected capsules.** Each failure records class, exact reproducer, dependency fingerprint and capsule obligations blocked. Prioritize expected complete responsibilities unlocked per engineering/qualification cost. Failed outcomes and caps stay retained; speculative yield is labeled an estimate. Retry on dependency change, not repeated messages.
5. **Later integrate checkpoint-aware playtesting** when games are actually being made. Reuse the existing System 1/System 2 controller and native scenario runner, with explicit phase/invariant contracts and controlled resources. Do not launch now.

Measure completed observable responsibilities and usable capsules, number of unresolved essential obligations, successful scenario transitions, semantic-review corrections, cache hits, repaired-class reuse and time from selected obligation to registered consumable capsule. Retain accepted/failed/cancelled attempts and pins. Record semantic work, publication, review and handoff wait timestamps alongside existing runner stages. Stage times may overlap; report critical path only with start/end evidence. Baseline at least one matched capsule before setting latency or throughput budgets. No measured end-to-end speedup, token savings, or numerical expected game completion rate is available today.

## Final verified updates

The cache/readiness fix is implemented and independently source-reviewed clear. Final receipts are `local/ir/pipeline-efficiency/depth-cache-fix/FINAL-source-manifest.json`, `verification.json`, and `cache-readiness-review/review.json`. The final source-pinned run passed **36 cache/readiness checks in 0.103788209 s**, with **six snapshot-readiness checks in 0.011021375 s**. Independent review ran no duplicate tests/native campaign. Typed interfaces and finite source-function dependency closure no longer imply complete systems; snapshot mechanics closure is zero without authoritative system evidence.

The fix includes transitive local static-import discovery, same-path causal fixture/explicit JSON content invalidation, a separate qualification-runtime fingerprint, and matching parameter-grid/vector-budget requirements for proof reuse. Legacy receipts without runtime signatures conservatively miss future reuse; historical proofs remain immutable. Dynamic imports, subprocess binaries/libraries and arbitrary external toolchain/environment changes remain outside static import discovery. The reviewed current static local tree is covered.
