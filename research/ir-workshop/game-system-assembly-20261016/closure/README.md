# Recovered enemy damage and reaction core

This is a reusable post-contact subsystem from Metroid Zero Mission. One accepted damaging hit changes the enemy's HP, reaction marker, flags and lethal state, including the original function's typed lethal result. A later eligible enemy update consumes the same HP/reaction/freeze/palette fields to choose its hit-reaction display. It is not a complete combat encounter.

`system.json` records the exact boundary, inputs, shared source identity, phases, required services and missing consumers. `impact-semantic-proposal-v2.json` retains the source/adapter proof for the package aliases. The publication owner retains metadata revision/native ancestry separately.

Run `python3 -B research/ir-workshop/game-system-assembly-20261016/closure/build.py --hp 10 --damage 3` to emit the actual pinned assembly, validator result and reusable C core here. This performs only JSON processing and existing L1 lowering. The code comes from recovered package bodies; the wrapper contains no handwritten replacement game logic. The source caller must invoke `apply_accepted_damage` and `advance_eligible_reaction` in their distinct source phases. The ordered graph records that causal order; it does not supply a scheduler or invent a same-frame call policy.

Run `python3 -B research/ir-workshop/game-system-assembly-20261016/closure/verify.py` for one small host compile and source-flow check. No emulator, original native campaign, game or ROM is created. The check covers nonlethal HP transfer, packed marker preservation, later display selection, countdown completion and lethal shared state. Expected coverage costs one tiny host compile/run; its actual durations are retained in `host-verification.json`. No comparable previous subsystem baseline exists; no speedup is claimed.

`run.py` accepts one bounded JSON object on stdin: `{"hp":10,"damage":3,"ticks":1}`. It returns real generated-core state after initialization, the accepted hit and each explicitly requested eligible reaction invocation. HP/damage fit source u16; ticks are capped at 64. Requests use separate temporary directories, compile with a 10 second timeout, execute with a 2 second timeout, and accept at most8192 input bytes. No caller-provided source, path or command is accepted. This is useful behavioral inspection with synthetic source context, not gameplay. It intentionally does not translate tick counts into seconds.

The host still owes hit eligibility and vulnerability, source world/scheduler identity, shared global state import/commit, effect allocation, projectile retirement, species death/drop continuation, and rendering the selected source palette. Those services cannot be stubbed while claiming source-system closure. Existing finite native component receipts, valid graph bindings and host core execution are three different claims; none certifies full combat or a complete game.

Retained representative clean host-core compile: 0.0356 seconds; host source-flow execution: 0.0541 seconds; complete host verification: 0.1422 seconds. The default bounded inspector request took 0.1262 seconds, including 0.0372 seconds compiling and 0.0545 seconds executing. Queue time is unavailable. These are separate local measurements with nested stages, not a CI/build SLA or before/after speedup. No cache was added for this small measured compile cost. Exact machine/toolchain/source/artifact context is in the JSON receipts.
