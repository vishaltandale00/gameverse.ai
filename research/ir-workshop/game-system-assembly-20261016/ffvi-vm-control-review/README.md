# FFVI raw-control mechanism and HP target source review

Scope: the source raw-p-code → joined SSA → ordinary symbolic L1 mechanism in `vm_ir.py`, and the concrete frozen FFVI `hp-candidate-v1` HP transaction. Source inspection found no remaining semantic blocker for this fixed actor-0 target. Full-game, variable actor, broader battle-system and general VM compatibility claims are outside scope. This report reuses retained qualification; it does not execute native code. Final exact pins and admission-proof status are in `review.json`.

## Control and SSA findings

Direct CALL is handled as a transfer into a pinned source instruction, after the instruction's ordered raw operations establish LR. Callee register/memory effects are expanded from raw p-code rather than hidden behind a calling convention. Direct branches preserve their source target, conditional branches explore both successors, and BX/RETURN destinations must evaluate to a proven control value. Only Thumb mode transitions are accepted. An incoming sentinel continuation is admitted only at an explicitly declared exit dispatch. Source PC/mode/callee gaps, unsupported effects and unresolved indirect targets reject.

A control-context key includes source PC, known LR, known r5 and continuation/entry-fact byte shadow. This keeps distinct continuation frames apart while sharing reconvergent source tails. Each joined block receives full register phis, with predecessor order and operands appended together. Source-effect statements preserve operation order. The compiler rechecks control operands, store addresses/spill values and fact-load addresses after all incoming edges have joined, so a fact used during first discovery cannot silently change when a later predecessor arrives. Path cycles and explicit source/CFG/step limits reject.

The byte shadow starts from explicit canonical RAM facts. Source stores invalidate overwritten bytes; unknown-address stores discard all known shadow bytes. Only exact source values restore shadow facts, and control-relevant bytes participate in context identity. Initial entry-domain facts must survive as exact native-visible state domains. Control-only continuation seed facts are removed from portable data state only when not used as data; other continuation spills retain the separately reviewed strict token codec.

Register and unique storage use SSA identities. Overlapping storage windows reject instead of silently aliasing partial registers; instruction-local unique storage is scoped by expansion step. Mutable LOADs remain ordered L1 snapshots. Entry symbolic register fields are snapshotted before any output field write. Every accepted exit serializes declared liveouts through explicit typed compiler ports; subsequent port remapping merges input/output names for the same logical register without changing snapshot values. Persistent source writes require liveout or clobber classification. Constant folding uses exact SSA/known-memory values; overflow/carry expressions preserve finite storage widths.

## Findings resolved during review

The original raw-control ingestion lacked explicit canonical span bounds, positive instruction coverage, nonempty p-code and terminal-transfer guards. The owner added these admission checks: even canonical ROM spans; contiguous exact 2/4-byte instruction coverage; nonempty instructions/p-code; no trailing operations after a control transfer. The actual HP regions already satisfy these conditions.

The original boundary also allowed duplicate symbolic input field names across different registers. The owner added a distinct-name check plus unique declared full-register liveout/clobber validation. The actual HP inputs `vm_r8` and `vm_r9` were already distinct. These changes address malformed-input admission; they do not broaden supported control flow.

A further generic control-shadow alias issue was identified: noncanonical mirrored RAM writes could alias canonical continuation bytes while using distinct shadow keys. The actual HP adapter has only canonical scalar RAM spans. The owner added early known LOAD/STORE canonical-access guards and final recovered global field/collection span guards. The retained 15th negative case injects a store to mirror `0300f000`, which aliases continuation seed `03007000`, and is rejected. These guards resolve the issue without adding mirror support.

## Concrete retained target

The candidate contains 12 pinned raw regions, 334 instructions, 393 joined blocks and 2228 normalized SSA operations. Its declared boundary fixes actor 0 and incoming frame roots and exposes r8/r9 as scalar state. The normalized canonical JSON digest matches the adapter's `normalized_l0_sha256`; all raw canonical digests match the adapter's source list. All retained native receipt artifact hashes match their current candidate files. Every actual raw instruction has nonempty semantics, lies within its exact span and places control transfer last. The admission-hardening comparison retains identical base source/L1/emitted payloads. The base adapter differs from the frozen native candidate only by the latter's added `native_abi` metadata; that native adapter is independently pinned by its qualification receipt.

The retained receipt reports 4096 passing original/generated native pairs, including 50 expected field-subset fixture cases, and 1,162,730 aggregate emulated CPU instructions. Total qualification wall time is 0.237229 seconds, with native comparison 0.076761 seconds; queue time is unavailable. These are the target owner's actual prior run measurements, not a rerun by this reviewer. Instruction count is aggregate oracle work, not a per-case or wall-time measure. The native ABI protects its declared continuation exits/preservation expectations; this review does not replace the separate ABI mechanism review.

No tests, builds, native campaigns or ROM rehashing were performed here. Review wall/queue timing is unavailable. No new CI job, dependency, numeric resource budget or broad qualification stage was introduced.
