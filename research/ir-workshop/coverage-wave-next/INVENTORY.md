## Target and current state

The target is a whole game rebuilt from executable IR plus semantically identified assets, with provenance for every output byte. Exact reconstruction from captured object/raw/opaque spans is a useful baseline but gives no IR or asset semantic credit. At this snapshot, none of the 33 games meets that target. The three exact source/object maps are MZM, Emerald, and FireRed Rev 1; only MZM has 104 freshly source-regenerated bytes in its map, while all three have zero IR-regenerated and data-regenerated bytes in that baseline. MZM’s newer private reconstruction separately reports three fresh IR modules and 2,067 identified palette/audio asset bytes, while 8,386,517 bytes remain mixed native/unknown. This is substantial partial evidence, not whole-game closure.

L0 is capture-harness evidence, not a source map. Every game has an L0 capture record (9,000 emulated frames, attract/frontend phases; unique-instruction count unavailable). L1 availability below means either a binary corpus export or a pinned source repository. Source file suffix counts are inventory clues only: they do not establish game/version matching, compilability, code coverage, or asset semantics. “ELF: yes” means a retained exact-pin build ELF is explicitly referenced by the inventory.

## Ranked tractable gaps and proposed next targets

Rank uses a practical test: pinned source root plausibly matching the game, source/code depth and identifiable data potential, followed by the smallest blocker to a first whole-function IR or data-regeneration receipt. It is not a coverage percentage. Repo/title/version mapping must be proved before treating a root as game source. The first ten are the proposed next assignments:

1. **Metroid Fusion** — root `local/decomps/mf@55b1a54b` (702 C, 677 assembly files by suffix); no exact build or source/IR/data spans. First action: verify ROM revision correspondence, produce matching baseline ELF/map, then choose one source-complete leaf and separately identify its referenced graphics/data. Its neighboring MZM work offers shared tooling, not evidence of Fusion coverage.
2. **Pokémon Mystery Dungeon: Red Rescue Team** — `local/decomps/pmd-red@013475aa` (715 C, 827 assembly, 35,382 PNG suffix entries). First action: verify exact ROM revision/source target, build a matching baseline, and map one code/data owner to identified assets. Huge asset opportunity, but suffixes are not asset semantics.
3. **The Minish Cap** — `local/decomps/tmc@6fb6dfb4` (632 C, 304 assembly); no exact build/IR spans. First action: pin target revision and build baseline ELF/map; select a self-contained function with resource table references.
4. **Final Fantasy Tactics Advance** — `local/decomps/ffta-decomp@7f0e9ad2` (144 C, 49 assembly), plus L1 corpus export. First action: resolve exact game revision/source mapping, then establish source-build identity and qualify a leaf with explicit dependencies.
5. **Pokémon Ruby** — `local/decomps/pokeruby@5784633c` (367 C, 33 assembly; 3,265 PNG/2,057 PAL/506 WAV suffix entries). First action: match ROM revision and build baseline; select one source-to-data chain and verify actual asset loaders/consumers.
6. **Mario Kart: Super Circuit** — candidate roots `local/decomps/mksc@3df89321` and `local/decomps/mksc-decompilation@31b953f0` (source/assembly plus candidate graphics/audio files). First action: resolve which root and ROM revision match; then baseline before any extraction. Two roots are alternatives, not additive coverage.
7. **Kingdom Hearts: Chain of Memories** — `local/decomps/khcom@5dc49b75` (269 C, 7 assembly, 200 `.inc`); weak-wave actual IR modules pass 256 native comparisons, but only 20 emitted bytes and zero installed ROM IR bytes. First action: close storage ownership for a bounded data/code location before extending the module.
8. **Wario Land 4** — `local/decomps/warioland4@abb7800a` (35 C, 151 assembly); weak wave proves one 96-byte behavior + 80-byte binding + 3,061-byte read-only asset package and a 3,245-byte replacement, yet whole-image reconstruction still has zero IR-regenerated bytes. First action: publish admitted package into a reproducible reconstruction path with independent asset attribution; then grow a source-closed parent.
9. **Mario & Luigi: Superstar Saga** — roots `local/decomps/mlss@b03634c2` and `local/decomps/MLSuperstarSaga@baae1031`; sparse first root, second has no file counts. First action: identify exact source root/revision and produce a matching build before spending on extraction.
10. **Sonic Advance** — listed root `local/decomps/sa2@393357f7` has 955 C and 12,118 PNG suffix entries but is named as Sonic Advance 2; the mismatch makes exact title/revision validation the exclusive first gate. Do not count its assets/functions for Sonic Advance unless source mapping proves it.

**Also high leverage but already active elsewhere:** MZM has the strongest partial IR/data chain; Emerald and FireRed Rev 1 have exact source builds/ELF/maps but remain object-captured at whole-image level. Keep them as closure tracks, while starting new-source tracks above so the fleet does not collapse to MZM. Aria’s pinned `cvaos` source is substantial but its existing substitution is native-relocated, not IR, and no matching whole-game build exists.

## Weak-coverage wave evidence and shared blockers

The current cohort is `status: bounded_wave_published_workers_released` with six lanes. The reported outcomes show why central package growth is not whole-game progress:

- **MMZ:** one 70-byte source initializer; conditional profile-2 group; whole-game/general ROM eligibility false.
- **Wario:** one actual IR entry replacement independently reviewed; source/asset attribution and installed-image path remain bounded.
- **KH CoM:** fresh IR modules passed; installed ROM IR remains blocked on storage ownership.
- **Dragon Ball Advanced Adventure:** exact 16 MiB retained reconstruction (24 function envelopes / 5 tables, 28 internal edges, 62 open external calls); 0 IR bytes. Initializer attempt blocked on callback `08018ec5`.
- **Driv3r:** exact retained baseline with 1,404 captured bytes and 8,387,204 opaque bytes; 0 IR. Contact root blocked on unresolved `080b655c`; math roots hit unsupported 64-bit `PIECE`/missing argument facts.
- **FF I & II:** predicate evidence entered package intake; no newly recovered source function.

The central wave’s reported **170 packages / five scoped capability groups** and MZM’s separate **three IR modules / 2,067 identified asset bytes** are useful library and build evidence. Neither measure is an output-byte coverage denominator. MZM still contains 8,386,517 mixed native/unknown bytes in the private reconstruction.

Top shared blockers are: exact source-to-ROM/version mapping (especially related game forks); source/ELF/map baselines for source-root games; captured binary exports lack semantic function boundaries and source maps; source callbacks/native services and global state remain open; asset suffix inventories do not establish ROM addresses, encoding, compression, consumers or full dependency closure; IR modules may be generated yet un-installable due storage/ROM ownership; exact raw roundtrip can preserve large opaque spans without qualifying them; and no game currently has complete IR + identified-asset output attribution.
