# Contact hazards across extracted combat systems

Two causal encounter experiments pass generated host-C scenarios. They are executable subsystem proofs, not playable games or ROMs. No template, source ROM modification, new dependency, export, or native campaign is used.

`python3 -B research/ir-workshop/mashup-experiments-20261016/combat/run.py` validates two actual component graphs, emits C with Composer and compiles/runs five bounded scenarios per candidate. Compilation timeout is20s and execution timeout3s per candidate. Each graph lists source calls as a phase inventory; the `probe.c` file implements the conditional runtime call schedule. An admitted linear inventory does not prove the authored branch scheduler.

The first candidate connects Tekken's four-by-four physical separation/contact refresh to an authored bump-hazard event. The same target has a separate Wario protection counter; its extracted zero-selector stored predicate suppresses an FFVI resolved-HP invocation. An unprotected bump changes HP10→7; a lethal bump changes3→0 and queues source KO bit128. This is source physical contact repurposed as a hazard, not recovered attack hit eligibility. Source world-box coordinates and actor positions remain Tekken's distinct formats; source effect/HP fields remain FFVI packed byte lanes. No MZM HP conversion is asserted.

The second candidate uses that physical/protection event to conditionally apply MZM accepted damage, then invokes its reaction at an explicit later eligible prepass and asks the Ripper source update gate. A nonlethal bump changes HP10→7, keeps reaction17 until that later phase, then decrements it to16 and suppresses live behavior. A lethal bump requests pose0x62 and permits the source death-request path. No species death or retirement code runs.

Disjoint world boxes and separation-disabled actors produce no new damage in fresh fixtures. Protected overlapping actors still physically separate (observed source positions1797/771) while HP remains10. This is meaningful player-facing collision/protection/consequence behavior, but only assertions and stdout observe it. Actual input, scene, hit animation, rendering/palette upload, audio, damage telegraph and death presentation remain absent.

Authored pieces: target association between independently typed records; bump-hazard design; conditional dispatch; caller-supplied box fixtures and damage magnitude; phase eligibility schedule; scenario initialization and assertions. Recovered pieces: all generated component functions and their exact package receipts. The Wario protection query does not age/reset the counter. FFVI fixed actor0/null-continuation specialization is respected by fresh-event fixtures; general repeated invocation requires entry-context reset. FFVI KO pending is not settled defeat. MZM enemy prepass schedule, species dispatch, contact admission, drop selector/effect pool/DMA/audio and enemy retirement remain external.

Critical next fix is an explicit encounter lifecycle wrapper: retain the source contact refresh, distinguish new contact admission, prevent further damage after terminal state, reset FFVI entry context, and schedule/age source protection in its own invocation units. Then implement pending-status realization or MZM species death/cleanup and a small renderer/input/restart loop. Neither graphics nor complete defeat can be inferred from current source flags.

`*.result.json` and `run.json` pin packages/IR/native receipts and record validation/build/run outcomes and timing. Native finite receipts are reused, not rerun. `legacy-mzm.attempt.*` captures the source graph as observed and its validation outcome; this run observed it valid after the other worker's repair, so it is not a new failure reproduction. Dirty working-tree dependencies need their retained hashes, not commit alone. Queue, CI, cache and original-ROM connected parity are unavailable. No before/after latency claim is made.

Independent temporal probe (`../playtest/combat-temporal.json`) disproves the stale-contact suspicion: a disabled next separation invocation clears source contact bit3 and retains HP7. It does expose a real authored lifecycle defect: the terminal HP0 target accepts another bump after the death-request gate and resets reaction16→17. This is the missing terminal exclusion/death-dispatch boundary, not a recovered-source parity failure. The failed stale-contact hypothesis and corrected executable are both retained by the probe worker.
